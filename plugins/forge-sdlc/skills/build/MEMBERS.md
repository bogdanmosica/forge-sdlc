# The member call

Every agent a forge-sdlc command starts is a **member**: an Agent call carrying a `name` from the host's crew theme. The skill that makes the call names its role and whether it runs in the foreground or the background; this file is the rest of the call, the same for every member. The **lead** is whoever makes the call: the command's own session, or the merger for the calls slice-review makes. The lead follows the skill's link, so this file is read by path and keeps its plugin-root variable unresolved: read each `${CLAUDE_PLUGIN_ROOT}` below as the plugin root the linking skill resolved.

A lead launched with agent teams enabled (as `cmux claude-teams` does) turns a named call into a teammate in its own visible pane, listed in cmux's Crew panel. A plain lead runs the same call as a subagent. The lead makes the same call either way, with the same brief, worktree and proof. A call that passes `isolation` on the call itself stays a subagent under both.

1. **Name.** Before the Agent call, from the project dir, run `node "${CLAUDE_PLUGIN_ROOT}/bin/crew-name.mjs" <role> --project "<project dir>" --effort <slug>`, adding `--slice <slug>-<nn>` for an implementer, and pass the one line it prints, unchanged, as the call's `name`. One run per call: three reviewers are three runs, each printing the next free name. A slice keeps its implementer's name across fix rounds and resumes, because the script prints the slice's name again. The name is display only: the prompt, branches, commits and records carry the slug and slice id. Done when the call carries `name`.
2. **Agent id** (implementer only). Right after the call, write the id the Agent result names as the slice's `agent`: `efforts.<slug>.slices["<slug>-<nn>"].agent`, through `readState` and `writeState` from `${CLAUDE_PLUGIN_ROOT}/hooks/scripts/lib.mjs` (`node --input-type=module -e`), with `updatedAt` now. The Stop hook finds the slice a stopping subagent built by this id, and a foreground call returns the id only after the subagent has stopped, which is why the skill starts an implementer in the background. Done when the state reads the id back on the slice.
3. **Wait.** The wait is "the member's report arrives". Under a plain lead, a foreground call's report is its return and a background call's is its task notification. Under a teams lead every member runs in the background (the Agent tool has no `run_in_background` there), and its report is the teammate's `idle_notification` mailbox message, whose `result` is the member's final message; it arrives on its own, so the lead waits for it. Under both, the report is a claim and the verify record is the evidence a slice is done. Done when the report is in hand.
4. **End.** Under a teams lead, end a teammate with a `SendMessage` shutdown request addressed to the member's name. An implementer ends once its slice merges or goes red; any other member once the lead has acted on its report (the researcher's note read, the spec-writer's spec committed, the verifier's record checked, the merger's report acted on). Under a plain lead a member is over when it has reported, and there is nothing to send. Done when every teammate whose work is settled was sent the request.
