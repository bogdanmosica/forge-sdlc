# What can the /forge panel draw to show the loop as a flow diagram, and does GitHub render a Mermaid block in a PR body and README?

## Answer
The engine has no diagram or graph renderer: the panel must lay boxes out itself from `Box` (flex row/column, `borderStyle`, `borderColor`, `gap`, `width`), `Text` (colour, bold, inverse, dim, `wrap`) and box-drawing or arrow characters, sized to `e.props.bodyColumns`. A horizontal five-stage chain does not fit the panel's 72-column body with gate chips, so draw it vertically (stage boxes stacked, gate rows between them) with a one-line-per-stage fallback when `bodyColumns` is small. GitHub renders a fenced `mermaid` block in PR bodies and Markdown files, so `bin/workflow.mjs --mermaid` can feed both; the Mermaid defaults (50000 chars, 500 edges) are far above a ~12-node chart.

## Findings
- No Mermaid, graphviz or diagram renderer is declared in the engine types or used by any hook: a search for mermaid/graphviz/diagram/flowchart over `plugins/forge-sdlc/hooks` finds only an unrelated Artifact tool description (file presentation of SVG/Mermaid in a side panel, not a panel element) ([claude-code.d.ts](../../../plugins/forge-sdlc/hooks/types/claude-code.d.ts)).
- The element set a render hook resolves is `Box`, `Text`, `Button`, `Link`, `Code`, `Markdown` (Ink's, allow-listed), plus `Image` (PNG/RGBA bytes, 1 to 255 columns wide) and `Raster` (a cell grid of printable width-1 BMP characters, "blocks, box drawing", 1 to 512 columns) ([claude-code.d.ts](../../../plugins/forge-sdlc/hooks/types/claude-code.d.ts), `$.ui.resolve` and Image/Raster sections). A Raster is a possible escape hatch for a pre-drawn grid; not tried (hypothesis on fit, below).
- `BoxProps` declare: `flexDirection`, `flexGrow`, `flexShrink`, `flexWrap`, `alignItems`, `alignSelf`, `justifyContent`, `gap`/`columnGap`/`rowGap`, `width`/`height`/`minWidth`/`minHeight` (number or string), margin and padding sets, `borderStyle` (typed as a bare `string`), `borderColor`, `borderDimColor`, `backgroundColor`, `overflow`, `display`, and `position: 'absolute'` with `top/left/right/bottom` integer offsets ([claude-code.d.ts](../../../plugins/forge-sdlc/hooks/types/claude-code.d.ts), `BoxProps`).
- `TextProps` declare `color`, `backgroundColor`, `dimColor`, `bold`, `italic`, `underline`, `strikethrough`, `inverse` and `wrap` (`wrap`, `end`, `middle`, `truncate`, `truncate-start|middle|end`); `size`, `mono`, `tabular` are ignored on the terminal ([claude-code.d.ts](../../../plugins/forge-sdlc/hooks/types/claude-code.d.ts), `TextProps`).
- Colour is a theme key (`success`, `error`, `warning`, `inactive`, `subtle`, `suggestion`, `permission`, ...) or a raw colour; theme keys follow the person's theme ([claude-code.d.ts](../../../plugins/forge-sdlc/hooks/types/claude-code.d.ts), `ThemeKey`, `Color`). Current stage = `inverse` or `bold` with a colour, a stopped gate = `warning`/`yellow` with a distinct glyph; the plugin already uses named colours and glyphs this way: gate glyphs `✓ ✗ ◔ ?` in green/red/yellow/gray ([focus.tsx](../../../plugins/forge-sdlc/hooks/focus.tsx), `GATE_GLYPH`, `GATE_COLOR`), and `color="yellow"` for the "you:" lines in the loop tab ([forge.tsx](../../../plugins/forge-sdlc/hooks/forge.tsx)).
- Width: a `Pane` render gets `e.props.bodyColumns`; `forge.tsx` opens with `columns: 72` and lays out at `Math.max(24, bodyColumns)`. `columns` is a request: the dock is at most 45% of the terminal and at least 24, the person may drag it, and inline (main screen) it takes the full width ([claude-code.d.ts](../../../plugins/forge-sdlc/hooks/types/claude-code.d.ts), `PaneOpenArgs`; [forge.tsx](../../../plugins/forge-sdlc/hooks/forge.tsx)). A pane opened by the person's own command is placed at any width. So 24 is the floor to design the fallback for, 72 the normal case.
- Inline panes get `rows` (default a third of the terminal); a taller tree scrolls ([claude-code.d.ts](../../../plugins/forge-sdlc/hooks/types/claude-code.d.ts), `PaneOpenArgs.rows`; band `maxRows`/`scroll`). A vertical diagram of five stages, four gates and agent lines is roughly 20-30 rows; request `rows` on open or accept scrolling.
- Wrapping and truncation: `Text wrap="truncate-end"` cuts at the edge with an ellipsis; the panel's existing tabs already use it for single-line rows and `wrap="wrap"` for prose ([forge.tsx](../../../plugins/forge-sdlc/hooks/forge.tsx)).
- Today's loop tab is a column of `Box`es: `LOOP` stage name (bold), text, yellow `you:` line, then the `GATES` string ([forge.tsx](../../../plugins/forge-sdlc/hooks/forge.tsx), [help.ts](../../../plugins/forge-sdlc/hooks/forge/help.ts)).
- Multi-column layout elsewhere is only `flexDirection="row"` plus `gap`, `flexWrap="wrap"`, `flexGrow`/`flexShrink` and `justifyContent="flex-end"`: the run band's figures row wraps and its H button sits at the right ([run-band.tsx](../../../plugins/forge-sdlc/hooks/run-band.tsx)); the run pane's agent rows and action row use `row` with `gap` ([run-pane.tsx](../../../plugins/forge-sdlc/hooks/run-pane.tsx)); `boards.tsx` and `focus.tsx` are columns of rows with a coloured glyph then text, grouped into lanes ([boards.tsx](../../../plugins/forge-sdlc/hooks/boards.tsx), [focus.tsx](../../../plugins/forge-sdlc/hooks/focus.tsx)). No file in the hooks module uses `borderStyle`, box-drawing characters or `position="absolute"`: a bordered-box diagram would be the first.
- GitHub renders Mermaid in "GitHub Issues, GitHub Discussions, pull requests, wikis, and Markdown files", from a fenced block with the `mermaid` language; the docs call out flowcharts, and say a third-party Mermaid plugin can cause errors; putting `info` in a mermaid block shows the Mermaid version GitHub runs ([GitHub Docs: Creating diagrams](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)). GitHub's page states no size limit and no unsupported-feature list.
- Mermaid's own limits that bind any renderer on the library: `maxTextSize` default 50000 characters and `maxEdges` default 500 ([Mermaid config schema](https://mermaid.js.org/config/schema-docs/config.html)); a ~12-node chart is two orders of magnitude under both.

## Hypotheses
- `borderStyle` accepts Ink's names (`single`, `double`, `round`, `bold`, ...) (hypothesis): the engine types it as `string` and no hook sets it; confirm by a throwaway `borderStyle="round"` Box in the stand-in host (`workbench.fixture.tsx`) and in a real pane.
- A horizontal five-stage chain needs about 90+ columns (five boxes of ~14 cells plus arrows), more than the 72 default and than the 24 floor, so the vertical layout with a narrow fallback is right (hypothesis): confirm by drawing it at 72 and 40 columns.
- `Raster` could carry a pre-laid-out grid with exact box-drawing, but its width is 1 to 512 and it must equal the mounted size, which the panel does not know at render time (hypothesis): confirm in the Raster section of `claude-code.d.ts` before relying on it; `Box`/`Text` are enough.
- GitHub's Mermaid supports `subgraph`, `classDef`/`class` styling and `click`-less nodes at the version it ships, and renders the same in a README and a PR body (hypothesis): the docs name flowcharts only; confirm by pushing a test block with subgraphs and `classDef` and reading `info`.
- GitHub applies a render-time size or time cap to very large diagrams (hypothesis): its docs state none; irrelevant at ~12 nodes, confirm only if the chart grows.
