# What does the Stop payload carry as cwd in a member, and does verified-before-stop read the slice branch correctly without change?

## Answer
The Stop payload's `cwd` is the session's current working directory at the moment the hook fires: it starts as the launch directory (the worktree, which crew.sh sets) and follows every `cd` Claude runs. So in a member the hook reads the slice branch correctly without change as long as the session has not `cd`'d out of the worktree. The implementer rule "first Bash call is `cd <worktree>`" is then redundant at launch but still matters as the guard against a later `cd` elsewhere, so keep it (reword only if desired). No code change is required; the smallest optional hardening is a test with a `Stop` payload whose `cwd` is a subdirectory of the worktree.

## Findings
- Common input field `cwd` is "Current working directory when the hook is invoked". ([hooks reference, common input fields](https://code.claude.com/docs/en/hooks))
- `cwd` follows Claude: "the `cwd` field in the hook's input JSON is the worktree root after Claude enters a worktree, and the new directory after Claude runs `cd`." Hence it is the last-`cd` directory, not a frozen launch directory. ([hooks reference, "Reference scripts by path"](https://code.claude.com/docs/en/hooks))
- `CLAUDE_PROJECT_DIR` is "the project root where the session started" and stays put; it does not follow `cd`. ([hooks reference](https://code.claude.com/docs/en/hooks))
- Stop input adds only `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons` to the common fields; the example carries a plain `cwd`. SubagentStop adds `agent_id`, `agent_type`, `agent_transcript_path`, `last_assistant_message`; its docs say nothing separate about `cwd`, so the open item from the first build (subagent cwd) is not answered by the docs. In a member the event is Stop, which is covered by the common-field rule above. ([hooks reference, Stop input and SubagentStop input](https://code.claude.com/docs/en/hooks))
- crew.sh spawn without `--worktree` uses `cwd="$repo"`; with `--worktree <branch>` it creates or reuses a worktree at `<parent>/<repo>-<slug>` and sets `cwd="$worktree"`. ([crew.sh lines 227-249](/Users/mosica.bogdan/.config/cmux/scripts/crew.sh))
- The member is launched with `cd <cwd>` in run.sh followed by `exec claude --agent <role> ...`, and the tab is also created with `--working-directory "$cwd"`, so the session starts in the worktree. ([crew.sh lines 279-294](/Users/mosica.bogdan/.config/cmux/scripts/crew.sh))
- The hook takes `cwdOf(payload)` (`payload.cwd || process.cwd()`), reads the branch with `git -C <cwd> branch --show-current`, matches it to the slice glob, and derives worktree (`--show-toplevel`), project (parent of `--git-common-dir`) and HEAD from that same cwd. Because the project is derived from git-common-dir, the verify record is read in the host, not the worktree, whatever the cwd subfolder. ([verified-before-stop.mjs](/Users/mosica.bogdan/Desktop/personal/forge-sdlc/plugins/forge-sdlc/hooks/scripts/verified-before-stop.mjs), [lib.mjs `cwdOf`, `currentBranch`](/Users/mosica.bogdan/Desktop/personal/forge-sdlc/plugins/forge-sdlc/hooks/scripts/lib.mjs))
- A cwd in any subfolder of the worktree gives the same branch (git resolves upward), so a `cd src/` is harmless; a `cd` into the main checkout or another repo would make the hook see `feat/<slug>` (or other) and silently allow the stop. This is what the implementer rule guards. ([implementer.md step 1](/Users/mosica.bogdan/Desktop/personal/forge-sdlc/plugins/forge-sdlc/agents/implementer.md): "every later one runs there: the Stop hook reads the branch of your working directory")
- Config lookup differs in a member: `projectDirOf` prefers `CLAUDE_PROJECT_DIR`, which in a member launched in the worktree is the worktree itself, so `docs/agents/forge.md` is read from the worktree's checkout (present if committed on the base of the slice branch), not from the host root. Branch-glob defaults apply if the file is missing. ([lib.mjs `projectDirOf`, `run`](/Users/mosica.bogdan/Desktop/personal/forge-sdlc/plugins/forge-sdlc/hooks/scripts/lib.mjs))
- Existing tests fake the payload as `{ hook_event_name: 'Stop', cwd: <worktree>, stop_hook_active: false }` and the SubagentStop variant with the same cwd; none uses a subfolder cwd or a cwd outside the worktree. ([tests/verified-before-stop.test.mjs](/Users/mosica.bogdan/Desktop/personal/forge-sdlc/tests/verified-before-stop.test.mjs))

## Hypotheses
- A member's `Stop` payload `cwd` after a `cd` in a Bash call reflects that `cd` at the exact Stop time (hypothesis): confirm by running a member that `cd`s to a subfolder and dumping the stdin payload from a throwaway Stop hook.
- The SubagentStop `cwd` for the old subagent implementer equals the parent session's cwd, not the subagent's last `cd` (hypothesis): the docs are silent; confirm with the same payload dump in a subagent run. Moot for members.
- `docs/agents/forge.md` is present in every slice worktree a member starts in (hypothesis): confirm that the file is committed on the effort branch the slice is cut from; otherwise the hook falls back to default branch shapes, which match the default `slice/<slug>-<nn>` only.
