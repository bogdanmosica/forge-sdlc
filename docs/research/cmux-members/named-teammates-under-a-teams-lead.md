# Named teammates under a teams lead: what a named Agent call does, and does `verified-before-stop` hold in one

## Answer

Under a teams-enabled interactive lead, an Agent call carrying `name` launches a teammate (a separate session, a split pane under `cmux claude-teams`), unless the call is a fork or passes `isolation`. `name` exists on the Agent tool in every session; without agent teams it only makes the subagent addressable, it is not an error. The docs state that a teammate's idle notification carries its final answer to the lead, and that a plain background subagent returns a completion notification; they do not say a named teammate launched as a background Agent call also gets the subagent's completion notification. The docs do not say which hooks fire in a split-pane teammate on stop, nor what its Stop `cwd` is after `cd`. So `verified-before-stop` holding in a teammate is unconfirmed; it holds only if Stop fires in the teammate session with the teammate's own cwd, as it does in a crew.sh member. The plugin definition's model and tools apply; `disallowedTools` is documented only for in-process teammates, and the name's allowed characters are undocumented. The first live build from a teams lead must confirm items 2, 3, 4 (disallowedTools) and 5 (see Hypotheses).

## Findings

Q1. Does `name` exist, and does it always make a teammate?
- The Agent tool accepts `name` on any session; the name makes the subagent addressable for later message or resume. ([sub-agents, Subagent names](https://code.claude.com/docs/en/sub-agents))
- In an interactive session with agent teams enabled, a subagent spawned from the main conversation with a `name` launches as a teammate, unless the call is a fork or passes `isolation` on the call itself. A frontmatter `isolation` does not prevent it, and the teammate then runs in the main session's working directory. ([sub-agents](https://code.claude.com/docs/en/sub-agents), [agent-teams, How Claude starts agent teams](https://code.claude.com/docs/en/agent-teams#how-claude-starts-agent-teams))
- No opt-in beyond the environment: "Claude launches a teammate when it calls the Agent tool with a name while agent teams are enabled"; Claude Code does not ask for confirmation. ([agent-teams](https://code.claude.com/docs/en/agent-teams#how-claude-starts-agent-teams))
- Enabling: `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`; without it no team is set up and Claude does not spawn teammates. With `-p` or the Agent SDK a named subagent runs as an ordinary subagent even when teams are enabled. Setting the variable to `0` makes named subagents launch as subagents again. ([agent-teams, Enable agent teams and Claude spawns teammates instead of subagents](https://code.claude.com/docs/en/agent-teams))
- Plain session: `name` is not absent, ignored or an error; the subagent runs as a subagent and the name works as a `SendMessage` address. `SendMessage` does not need agent teams (only structured team-protocol messages do). ([sub-agents](https://code.claude.com/docs/en/sub-agents), [agent-teams](https://code.claude.com/docs/en/agent-teams#claude-spawns-teammates-instead-of-subagents))
- `cmux claude-teams` sets the teams variable and makes every named teammate open as a split pane; plain `claude` runs teammates in-process. ([cmux-crew SKILL section 1](/Users/mosica.bogdan/Desktop/personal/cmux-config/skills/cmux-crew/SKILL.md)) The docs: `--teammate-mode auto` gives split panes inside tmux or iTerm2 with `it2`, otherwise in-process; default is in-process. ([agent-teams, Choose a display mode](https://code.claude.com/docs/en/agent-teams#choose-a-display-mode)) The mode is a property of the lead's launch, so one lead can fall back to in-process teammates.
- A teammate loads the lead's project context but not its conversation history; it receives only the spawn prompt. It starts with the lead's permission mode (not `dontAsk`); no per-teammate mode at spawn. ([agent-teams, Context and communication, Permissions](https://code.claude.com/docs/en/agent-teams))

Q2. How does the lead learn of completion?
- Teammate: "when a teammate finishes and stops, it automatically notifies the lead and includes its final answer in the notification"; one ending on an API error notifies the lead with the error text. Messages are delivered automatically, the lead need not poll. ([agent-teams, Context and communication](https://code.claude.com/docs/en/agent-teams#context-and-communication))
- Plain background subagent: its report arrives as a completion notification in a later turn. ([sub-agents, Run in foreground or background](https://code.claude.com/docs/en/sub-agents))
- `TeammateIdle` and `TaskCompleted` are hooks that can block, not channels the lead reads; both carry `teammate_name`. `TaskCompleted` fires on `TaskUpdate` completion or when a teammate ends its turn with in-progress tasks. ([hooks, TeammateIdle, TaskCompleted](https://code.claude.com/docs/en/hooks))
- Agents without the Task tools coordinate through messages only. ([agent-teams, Assign and claim tasks](https://code.claude.com/docs/en/agent-teams#assign-and-claim-tasks))

Q3. Hooks and Stop `cwd` in a teammate
- Documented teammate hooks: `TeammateIdle` (input: common fields plus `teammate_name`, `team_name` deprecated, `agent_id` for in-process teammates from v2.1.290; exit 2 keeps the teammate working; `continue:false` stops it) and `TaskCompleted`. ([hooks](https://code.claude.com/docs/en/hooks))
- `SubagentStop` input carries `agent_id`, `agent_type`, `agent_transcript_path`, `last_assistant_message`, plus common `cwd`; Stop and SubagentStop block by exit 2 or `{"decision":"block","reason":...}`. `cwd` is "current working directory when the hook is invoked". ([hooks](https://code.claude.com/docs/en/hooks))
- The hooks reference excerpts read do not state whether Stop or SubagentStop fires for a teammate, nor what `cwd` is after a teammate's `cd`.
- Local first-party evidence: the cmux hook header says Stop fires when "a lead or teammate finished a turn" and is wired in `~/.claude/settings.json` for Stop, SessionStart, SessionEnd. ([claude-team.sh](/Users/mosica.bogdan/Desktop/personal/cmux-config/hooks/claude-team.sh)) That is the user's own description of a split-pane teammate, which is a separate Claude process that loads the same settings (agent-teams: a teammate loads the same project context as a regular session).
- A split-pane teammate is launched with `--agent-name --team-name --parent-session-id`; cmux reads these from the session's launch arguments. ([refresh-teams.sh](/Users/mosica.bogdan/.config/cmux/scripts/refresh-teams.sh))
- What the hook needs: `verified-before-stop` reads only `cwdOf(payload)`, then `git` from that dir for the branch, toplevel, common dir and HEAD; it never reads `agent_id`, `agent_type` or `teammate_name`; it handles Stop and SubagentStop alike. ([verified-before-stop.mjs](/Users/mosica.bogdan/Desktop/personal/forge-sdlc/plugins/forge-sdlc/hooks/scripts/verified-before-stop.mjs)) So it needs one thing: a Stop or SubagentStop whose `cwd` is inside the slice worktree.
- Danger: when `isolation` is not passed, "the teammate then runs in the main session's working directory", so the worktree comes only from the implementer's own `cd <worktree>`; if the payload `cwd` stays at the lead's directory, the hook is quiet (allow) there. ([sub-agents](https://code.claude.com/docs/en/sub-agents))
- A blocked Stop in a teammate: `TeammateIdle` exit 2 also keeps a teammate working, and its `cwd` is a common field, so a `TeammateIdle` entry of the same script is a possible second gate (not needed unless Stop does not fire). The existing check blocks via `decision:block`, which TeammateIdle does not read (it uses exit 2 or `continue:false`), so reuse would need a hook change. ([hooks](https://code.claude.com/docs/en/hooks))

Q4. `subagent_type` from a plugin
- Teammates can reference a subagent type from project, user, managed or plugin scope; plugin agents are addressed by the scoped identifier `<plugin>:<agent>`. ([agent-teams, Use subagent definitions](https://code.claude.com/docs/en/agent-teams#use-subagent-definitions-for-teammates), [sub-agents, plugin matcher](https://code.claude.com/docs/en/sub-agents))
- Applied: `tools` limits the teammate (in-process teammates also get `SendMessage` and Task tools added); `model` is used in either display mode when the spawn prompt names none; body: appended to the default prompt for in-process, replaces the default prompt for split-pane. ([agent-teams](https://code.claude.com/docs/en/agent-teams#use-subagent-definitions-for-teammates))
- `disallowedTools`: documented only for an in-process teammate ("for an in-process teammate, Claude Code removes the tools..."). The split-pane entry for it is not stated. `effort` likewise in-process only; `skills` never applied (the teammate loads skills from project and user settings). ([agent-teams](https://code.claude.com/docs/en/agent-teams#use-subagent-definitions-for-teammates))
- A definition from a project `.claude/agents/` dir is re-applied on revival only if the folder is trusted. ([agent-teams](https://code.claude.com/docs/en/agent-teams#use-subagent-definitions-for-teammates))
- Matches the local cmux-crew claim that a `subagent_type` gives the teammate that definition's prompt, tools and model. ([SKILL section 1](/Users/mosica.bogdan/Desktop/personal/cmux-config/skills/cmux-crew/SKILL.md))

Q5. Name display and characters
- Roster: `~/.claude/teams/<team>/config.json` `members[]` with `name`, `color`, `model`, `prompt`, `cwd`, `isActive`, `agentType`; the lead is `team-lead`. Not hand-editable. ([agent-teams, Architecture](https://code.claude.com/docs/en/agent-teams#architecture); [refresh-teams.sh](/Users/mosica.bogdan/.config/cmux/scripts/refresh-teams.sh))
- cmux folds the roster into a `TEAM <team>;<lead surface> <name>;<color>;<surface>;<alive>;<model>;<prompt>|...` workspace line; the Crew panel shows the name as the first field verbatim after `clean`, which replaces runs of `;`, `|`, newline, CR and tab with one space and trims. The match from roster to tab is by `--agent-name` equal to the member name. ([refresh-teams.sh](/Users/mosica.bogdan/.config/cmux/scripts/refresh-teams.sh))
- `team-pane.sh` takes the name as the argv element after `--agent-name`, but if `launch_arguments` is a string it splits it on whitespace, so a name with a space would be cut to its first word in that path. ([team-pane.sh](/Users/mosica.bogdan/.config/cmux/scripts/team-pane.sh))
- Allowed characters of the Agent `name` parameter are not documented; the frontmatter `name` rules (256 chars, no leading `-`, no `:`) are a different field. Each agent's mailbox is the file `~/.claude/teams/{team-name}/inboxes/{agent-name}.json`. ([sub-agents](https://code.claude.com/docs/en/sub-agents), [agent-teams](https://code.claude.com/docs/en/agent-teams#architecture))
- The name need only be a plain slug to be safe on every path read here; `<slug>-<nn>` fits.

## Hypotheses

- A named background Agent call that launches a teammate also brings the lead back by a notification carrying the final report, as idle notifications describe (hypothesis): the first live build checks that the lead is woken without any poll and that the text includes the implementer's report. Backstop already decided: the verify record is the evidence.
- Stop fires inside a split-pane teammate with the teammate's own `cwd`, i.e. the worktree after `cd` (hypothesis): confirm by logging the Stop payload (`cwd`, `agent_id`, `hook_event_name`) in a live teams-lead build, in both split-pane and in-process mode; if it fires as SubagentStop, the hook already covers it; if only TeammateIdle fires, a hook change is needed.
- In in-process mode the `cwd` in hook payloads follows the lead's directory, not the teammate's `cd` (hypothesis): confirm in the same log.
- A split-pane teammate honours the definition's `disallowedTools` (hypothesis; docs state it only for in-process): confirm by checking that a teammate of `forge-sdlc:implementer` lacks the tools the definition denies.
- The `forge-sdlc:implementer` plugin type is resolved for a teammate by its scoped name (hypothesis; docs name plugin scope as allowed, no worked example): confirm the roster entry's `agentType` and the pane's model.
- Apostrophes and spaces in `name` work in the roster, the mailbox filename and the cmux panel (hypothesis; undocumented, and one cmux path splits a string on whitespace): confirm with a name like "O'Brien" in a live lead; until then use `<slug>-<nn>`.
- Passing `isolation` on the Agent call yields a plain subagent under a teams lead (documented as the exception; whether the forge build wants that as its explicit fallback is untested).
- Under `cmux claude-teams` the lead's `--teammate-mode auto` gives panes only where tmux/iTerm2 applies; cmux's tmux shim is what makes panes appear (hypothesis, from team-pane.sh comments): confirm by a live spawn.

First live build must confirm: notification path (Q2), Stop/SubagentStop cwd in both display modes (Q3), `disallowedTools` in split panes (Q4), and name characters (Q5).
